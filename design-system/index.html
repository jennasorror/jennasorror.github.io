Portfolio Design System

I built this system while designing my portfolio. I wanted some personality in the interface, but I also needed the case studies to be comfortable to read. Having shared styles gives me a starting point when I add a page or change a component.

02 / Typography

I liked Space Grotesk for the headings and paired it with DM Sans for the longer passages. I wanted the two to feel related without making every part of the page look the same. Both fonts are hosted locally.

05 / Tokens
I name shared variables by what they are used for. That helps me find the right value to change and see which components will be affected. The examples below show how those names connect to the CSS.
How the styles reach the interface
I use shared values for things like color and spacing, with component variables referring back to them. When I change a button, I can follow that reference rather than add another value just for one page.
01 / Valuesdesign-tokens.css
Palette, type scale, spacing, and component aliases.
02 / Shared rulessystem.css
The final shared layer for navigation, cards, controls, and responsive layouts. Base and page-specific styles load before it.
03 / Behaviorapp.js
Gallery selection, image dialogs, reading settings, and focus return.

06 / Accessibility
I check accessibility as I work on each component. A color pair might pass on its own, but I still need to check how the whole component reads and behaves, including with a keyboard.
Checks I carry into each change
  1. ComponentCan I use a role I already have, or does this need a new one?
  2. InteractionCan someone use it with a keyboard and tell where they are?
  3. LayoutDoes the content still work on a small screen or when enlarged?
  4. EvidenceIs the result clear, with its unit and enough context to read it fairly?
